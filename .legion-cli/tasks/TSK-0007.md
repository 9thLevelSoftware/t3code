# Provide equivalent MiMo instance setup and lifecycle controls on mobile

Acceptance: AC-P0-01, AC-P0-02, AC-P0-03, AC-P0-05, AC-P1-01, AC-P1-02, AC-P1-03, AC-P1-04, AC-P1-05, AC-P1-06, AC-CH-01.

FileContract: only contract.filesAllowed may be changed; other source files are read-only. Preserve WIP and task ownership. No approval, commit or publishing is implied.

Planned command identities: C-MOBILE.

## Observable result

The existing Provider Accounts screen is not a generic provider-instance editor. Add a provider-instance setup route reachable from existing Settings without disturbing account authentication flows. Register MiMo's browser-safe client definition and build a small native form reusing its schema and existing mobile fields. Avoid creating a second validation/configuration system or a general form-builder project.

Support named stable instances, Token Plan region/custom endpoint and explicit model IDs, secret presence/replace/clear, destination-host prerequisite feedback, save/edit/disable/re-enable/remove, truthful busy errors and catalog refresh. Show saved versus runtime/model available versus actual live coding evidence distinctly. All mutations use the shared environment command with the explicitly selected destination, its permissionAtom and a fresh execution-time grant check. Never store API keys in local mobile preferences, URLs, navigation params or diagnostics.

Composer selection and existing saved threads retain instance identity through refresh, disconnect/reconnect, disable/remove and re-enable. A disabled/removed or unavailable runtime stays visibly unavailable; do not switch provider/model silently. Match web guidance for auth, region/model, quota, network and cancellation settlement without automatically starting coding or login. Accessibility, keyboard/form submission and busy controls use existing native conventions.

## Verification

C-MOBILE uses the existing React Native component test harness for the proposed new screen test plus existing navigation/scoping and provider helper tests. Drive meaningful create/edit/replace/clear/disable/re-enable/remove interactions; observe resulting destination requests, rejected unauthorized/busy actions and displayed redacted state. Cover two environments with identically named instances and two independently configured endpoints. Route reachability is asserted through the Settings route test/harness, not by testing a constant in isolation. Do not claim a model-helper test proves the native setup interaction.

M-CLIENTS later exercises iOS/Android and a remote environment after explicit device authorization; the primary integrator runs one pass. No simulator/device, Metro, browser or dev server is started by this planning job or subagents. Native build prerequisites are part of that future procedure, not evidence already obtained.

TSK-0001 owns apps/mobile/vite.config.ts and registers this new screen test in reactTests. This task owns the actual screen test. C-MOBILE must run it in the React/jsdom project after both dependencies complete; no duplicate configuration ownership is granted.
