# Qualify the MiMo release and isolated headless protocol before implementation

Acceptance: AC-P0-01, AC-P0-04, AC-P1-02, AC-P1-04, AC-P1-07, AC-P1-08, AC-P1-09, AC-CH-01.

FileContract: only contract.filesAllowed may be changed; other source files are read-only. Preserve WIP and task ownership. No approval, commit or publishing is implied.

Planned command identities: Q-CLI.

## Outcome and scope

Resolve ASM-0010 through ASM-0014 with evidence from one identified, user-installed MiMo-Code release before any product implementation. This task owns two lasting real-CLI qualification tests; it does not enable a product adapter or register the provider. It may begin read-only research after plan approval; readiness is not a claim that the prerequisites are already qualified. No adapter override is specified: MiMo is the product runtime under investigation, not a requested Legion coding harness.

Read current primary MiMo repository/release and Token Plan documentation. Record source URLs, source commit/tag, exact release/version output, binary identity, host OS/architecture, documented regional endpoints and supported coding model IDs in a redacted structured report emitted to stdout, with limitations retained in the task run summary. Do not infer a MiMo version from OpenCode versions or use stale endpoint/model guesses. No runtime redistribution, automatic installer, global config edits or separate OpenCode dependency.

Build a small qualification harness and loopback Chat Completions fixture in the two allowed .mjs files. Run the actual identified CLI with synthetic credentials and disposable per-instance directories, never the developer's live T3 home or global provider files. Record fixture and command digests. Prove the selected CLI cannot read/write unrelated global/project config; use sentinel files and before/after hashes. If its documented isolation switches cannot meet this boundary, fail the gate rather than launching against live configuration.

Probe version success/failure, missing/unsupported versions, headless readiness/authentication, config injection and the documented Chat Completions path. Demonstrate streaming, tool calls/reasoning metadata, approval/denial, unchanged permissions, two independent instances, per-thread T3 MCP routing, cancellation completion and restart/reconnect/continuation. Exercise a Token Plan-shaped preset and a separate custom endpoint/model/key through the same configuration shape. The endpoint fixture supplies controlled responses; it does not prove MiMo service entitlement or live interoperability.

Trace the existing T3 typed secret path with synthetic instance IDs: persistence, replacement/clear, materialization into only the owning runtime and redacted logs/projections/exports. Qualify the proposed seam without importing a new product adapter. Demonstrate owning-instance catalog refresh/rebuild and continued identity of the other instance. If a requirement cannot be proved with the existing seam and isolated probe, record it unresolved and stop dependent work.

## Verification and gate

Q-CLI must execute real CLI protocol probes against the loopback fixture and assert observations, not merely validate an evidence file. It must fail on missing runtime, unverified pin, absent mandatory observations, unexpected global writes, or unresolved isolation. Use event/deferred/stream acknowledgements, no polling sleeps or retry-based success. Emit only redacted summaries and hashes to captured task output and the execution run summary; keep secrets and raw potentially sensitive output out of evidence. The task owns the two lasting qualification test sources, never Legion workflow files.

Completion requires a per-assumption evidence table with every mandatory capability passed, or an explicit failed/unavailable result that leaves TSK-0003 and every dependent task blocked. Fixture-only success is not live qualification. If a real account, paid call, browser/device action or external installation is needed, stop that portion for separate authorization; do not mark the gate complete by weakening the requirement. No successful prerequisite checks are rerun without new changes or unresolved evidence.

## Handoff and limits

Deliver the exact supported-release policy, configuration injection method, transport/session contract, region/model metadata and justified code-sharing decision to TSK-0003/0004. The design defaults to a separate implementation with no OpenCode adapter refactor. If evidence demands different interfaces or files, use a new approved contract increment rather than widening downstream FileContracts. Later live and cross-platform procedures remain pending in the board.
