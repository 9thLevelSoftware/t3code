# Implement the qualified MiMo runtime adapter and independent instance catalog

Acceptance: AC-P0-01, AC-P0-02, AC-P0-04, AC-P1-01, AC-P1-03, AC-P1-04, AC-P1-05, AC-P1-06, AC-P1-07, AC-P1-08, AC-P1-09, AC-CH-01.

FileContract: only contract.filesAllowed may be changed; other source files are read-only. Preserve WIP and task ownership. No approval, commit or publishing is implied.

Planned command identities: C-RUNTIME.

## Observable result

Implement a distinct mimo ProviderDriver and ProviderAdapterV2 using only the release/protocol demonstrated by TSK-0002. Keep MiMo's supported-version policy independent of OpenCode v1/v2 classification. Missing executable, unsupported version, failed probe and failed readiness each produce actionable redacted destination-host guidance. Runtime installation remains user-managed.

Each create owns a scoped runtime, per-instance persistent state/config and only that instance's materialized credential. Inject secret values through the qualified runtime-only channel; use protected managed files only if the qualification demonstrated them, with retention/cleanup and redaction tests. Preserve resume state across a safe rebuild; do not treat disposable process configuration and durable session state as interchangeable. Never write user-global MiMo/OpenCode files or inherit uncontrolled unrelated provider credentials. Thread-specific T3 MCP routing and permissions remain isolated within the runtime model qualified by TSK-0002.

Normalize streaming text, reasoning metadata, tool events and approval round-trips into existing contracts. Implement cancellation acknowledgement versus terminal settlement distinctly, unexpected exit/network failure, session reattachment/reconnect and restart/resume; preserve continuation identity and report unsupported continuation without reassignment. Respect existing sandbox and approval policy without an allow-all fallback. A successful start request is not completion.

Use the explicit model IDs and qualified capabilities to publish only supported coding models. Refresh/rebuild invalidates only the owning instance's catalog/status. Keep saved, available and live-verified evidence separate; never grant live verification from a fixture, status poll, model listing or basic API completion. Background checks do not start coding or login. Classify auth, expired key, rate limit, quota, malformed configuration and network failures safely; never switch account/region/model/billing route automatically.

The qualification evidence may justify calling existing exported utilities, but this task does not own OpenCode files. Default to the distinct adapter. Shared mutable runtime state or speculative OpenCode extraction is excluded; required extraction uses a separately approved increment.

## Verification

C-RUNTIME uses deterministic process/protocol fixtures with synthetic keys. Exercise both preset and custom paths, two simultaneous instances, independent refresh/state/secrets, missing/unsupported releases, readiness failure, auth/quota/network errors, bounded streamed metadata, tool permissions, approval denial, cancellation before/after start, late terminal events and continuity after restart. Fail tests on forbidden global writes, plaintext projected/logged secrets, automatic fallback or background coding/login. Use Deferred, Queue or protocol events; wall-clock tests only for actual process/network fixtures, never sleep-based settlement.

Expose a minimal reusable testing entrypoint for the final orchestration fixture. These checks establish adapter behavior against qualified fixtures; live MiMo service and cross-platform compatibility remain external gates.
