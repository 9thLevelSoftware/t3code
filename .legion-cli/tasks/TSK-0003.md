# Define reusable MiMo instance settings, presets and destination permission guards

Acceptance: AC-P0-01, AC-P0-02, AC-P0-03, AC-P1-01, AC-P1-02, AC-P1-03, AC-P1-07, AC-CH-01.

FileContract: only contract.filesAllowed may be changed; other source files are read-only. Preserve WIP and task ownership. No approval, commit or publishing is implied.

Planned command identities: C-CONFIG.

## Observable result

A browser-safe MiMo provider definition supplies one reusable schema for named stable instances: enabled state, destination-host binary, Token Plan region or custom Chat Completions base URL, typed secret credential and explicit model IDs/coding capabilities. Presets include China, Singapore and Europe only with metadata verified by TSK-0002. No automatic region/account/model/billing fallback. Reject mismatched preset region/endpoint and malformed/unsupported route/model settings. A custom endpoint is a first-class path through the same schema.

Keep MiMo settings/client metadata in packages/provider-mimo, depending on the existing contracts helpers and provider-core. Contracts remain provider-package independent. Reuse secretSetting annotations and the existing ProviderInstanceMutation and server.updateSettings payload; do not introduce a parallel config store, runtime loop or new RPC solely for this provider. Stable instance IDs remain separate from display names and runtime session IDs. Saved settings must never imply runtime availability or live verification.

Add server.updateSettings to CLIENT_GUARDED_RPC_SCOPES with payload-sensitive required scopes matching server authorization: provider instance mutations require providers:manage, general patches retain their existing scoped requirements, mixed payloads require both as applicable. Keep createEnvironmentRpcCommand and its permissionAtom authoritative for client availability, recheck routed destination grants on execution, and preserve unrelated settings behavior. Do not substitute a blanket settings grant for provider permissions.

This task exclusively owns all package manifests/lockfile changes for the new package, including consumer workspace dependencies and root explicit workspace tooling registration where required. Keep exports limited to the planned client/settings/server/testing entrypoints; server-only modules must not enter client bundles. Before installing, honor .t3 setup markers and existing setup activity. No install is run by the planning job. Later dependency resolution uses repository vp conventions and must remain within these files; unexpected generated source edits require an amendment.

## Verification

C-CONFIG: test-first schema/preset cases, invalid endpoint/region/model combinations, explicit secret replace versus clear semantics, synthetic keys never echoed, and correct target environment/provider scopes including revoked grants while a command waits. Existing settings tests are a regression reference; no edits to that file are granted here. Verify the non-preset case has a different model/key/base URL, not a renamed preset.

There is no runtime or live availability claim in this task. Consumers register the definition in later tasks. Whole manifest ownership is grouped here so later task owners request an amendment rather than edit shared manifests. Package typechecks run once at the integrated boundary after the declared server exports exist.
