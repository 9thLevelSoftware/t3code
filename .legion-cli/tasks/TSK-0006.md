# Expose MiMo setup and truthful availability through web and desktop provider surfaces

Acceptance: AC-P0-01, AC-P0-02, AC-P0-03, AC-P0-05, AC-P1-01, AC-P1-02, AC-P1-03, AC-P1-04, AC-P1-05, AC-P1-06, AC-CH-01.

FileContract: only contract.filesAllowed may be changed; other source files are read-only. Preserve WIP and task ownership. No approval, commit or publishing is implied.

Planned command identities: C-WEB.

## Observable result

Register MiMo in the existing provider registry and use schema-driven settings/onboarding. Add only the feature-specific controls needed to choose Token Plan region or custom endpoint, explicit model IDs, binary prerequisite and secret replace/clear. Respect selected destination environment for every action, including a desktop renderer controlling a remote environment. Use command permissionAtom; expose redacted presence only, preserve form names/values, keyboard/labels, pending/disabled states and error handling.

Show named instance ownership and saved configuration separately from runtime/model availability and actual live coding evidence. Invalidate stale availability/verification when configuration changes. Present missing/unsupported host CLI, invalid region/model, invalid/expired key, rate/quota and network failures actionably. No setup/status action starts coding or login. A busy mutation is rejected server-side and the UI explains wait or explicit cancel; it must not optimistically remove/disable the instance or treat cancellation acknowledgement as settlement.

Provide edit, disable, re-enable and remove with preserved saved-thread visibility and no silent provider selection fallback. The normal catalog should populate the chat picker, project defaults, Settings model selectors, command palette/keybindings and scheduled-task model selection. Audit these consumers for hard-coded driver filters; use the shared catalog/helper path and preserve unrelated providers. If an entrypoint needs edits outside this exact list, stop for a contract amendment instead of quietly omitting it.

Desktop uses this web UI and the selected environment server; no separate Electron provider UI, OAuth return path or IPC is planned. Both hosted and locally served web must keep the existing single-origin/remote routing behavior; do not bake localhost origins into bundles.

## Verification

C-WEB extends meaningful existing unit/schema/helper tests for target selection, preset/custom setup, redacted replace/clear, available/disabled/removed model selection and all distinct status states. Do not use static markup assertions or callback-only tests. This command intentionally contains no browser tests. Static checks do not establish actual client interaction or visual quality.

M-CLIENTS is the separately authorized real-client procedure in the board, owned for integrated execution by TSK-0008: capture before/after setup changes and exercise web/local/hosted plus desktop remote destination. Do not launch browsers or computer use merely to complete this task. Missing authorization remains pending evidence, not a passed acceptance result.
